# Architect Review Checklist

Every item must be ticked or reported as unverifiable with a reason.

- [ ] Problem, constraints and decision are stated.
- [ ] At least one alternative was considered, with reasons for rejection.
- [ ] Fits the profile's layout, boundaries and dependency direction.
- [ ] Profile architecture rules and forbidden patterns respected.
- [ ] Data ownership and integration boundaries are clear.
- [ ] Failure modes, scalability and operability addressed.
- [ ] Security guardrails and trust boundaries addressed.
- [ ] New dependencies justified, pinned and reversible.
- [ ] Testability and migration or rollback path described.
- [ ] Irreversible aspects flagged for explicit user acknowledgement.
- [ ] Nothing edited, run or committed (read-only).
